## 正式回归测试

报告里列的每条问题都落成了可执行断言：

```bash
npm test              # 规则引擎单测（22）
node test/run-all.js  # 全量回归：11 个套件，自己起服务、跑完自动清理
```

`test-reports/` 下的 4 个 `.test.js` 是 B 报告里的「方案承诺 ↔ 代码实现」对表测试，
断言的是**修复后的正确行为**，属于回归防线，必须跟着代码一起维护。

| 文件 | 用例数 | 覆盖 |
|---|---|---|
| `api-parity.test.js` | 14 | HTTP 层行为与方案一致性 |
| `edge-cases.test.js` | 26 | 边界场景（跨天跨周、午休、补卡、封顶…） |
| `rules-spec-parity.test.js` | 35 | 24 个真实场景 + 10 项规则参数逐条对表 |
| `spec-math.test.js` | 8 | 时长换算的数学正确性 |

审查过程中的一次性脚本（临时环境模拟、调试探针）未收录 —— 它们依赖沙箱的绝对路径，
在别的机器上跑不起来，留着只会误导。需要复现某条结论时，
按报告里写的复现步骤手写一个断言更快。

另见 `test/doc-consistency.js`：校验 README 和《使用手册》里的每个数字、字段名、
接口路径与代码里的真值一致，防止文档悄悄过期。
