## 1. 先搞清楚这是什么东西

办公室门口那台闲置的安卓手机 → 变成**打卡终端**（只负责显示二维码和在场人数）。
员工自己的手机 → 打开网页 → 扫终端二维码 → **按自己的指纹** → 打卡完成。

**指纹按在员工自己的手机上，不按在旧手机上。** 手机的指纹硬件跟设备绑死，
旧手机上按指纹只能证明「这台设备被它的主人解锁了」，证明不了谁站在旁边。
反过来，员工自己手机的指纹就是最好的身份证明：免费、零维护、零误识。

技术上用的是浏览器原生的 **WebAuthn**：指纹/人脸模板只存在员工手机的安全区，
服务器收到的只是「验证通过」这个布尔值，拿不到任何生物特征数据。

**代价**：因为指纹按在员工手机上，所以**扫码这一步是必须的**（每 45 秒换一个新码）。
一次打卡 ≈ 3 秒：解锁手机 → 扫码 → 按指纹。

## 2. 安装部署

### 2.1 你需要准备什么

| 项 | 要求 | 说明 |
|---|---|---|
| 一台电脑 | 能 7×24 跑一个 Node 进程 | 办公室那台闲置笔记本也行 |
| 一台旧安卓手机 | 能装 Chrome、屏幕不坏 | **不需要 root** |
| 一个域名 | ≈ ¥30–70/年 | 指纹功能要求 HTTPS，见 2.4 |
| Node.js | **≥ 22.13** | 用了内置 `node:sqlite`，老版本没有 |
| Docker（可选） | — | 有的话更省事 |

> 为什么必须有域名 + HTTPS：浏览器的硬性安全规则。
> 用 `http://192.168.x.x:8080` 打开，浏览器会**整个禁用**指纹能力，
> 员工看到的是「这个浏览器不支持指纹验证」，而真实原因是地址不是 HTTPS。
> 这不是本项目的限制，绕不过去。

### 2.2 方式一：Docker（推荐）

```bash
git clone <这个仓库> presence-beacon && cd presence-beacon
cp .env.example .env
# 按 2.4 改 .env 里的 RP_ID / APP_ORIGIN
docker compose up -d
```

数据在挂载卷 `/data` 里，容器重建不丢。

### 2.3 方式二：直接跑 Node

```bash
npm install
cp .env.example .env
# 按 2.4 改 .env
npm start
```

### 2.4 配置 HTTPS（**必做，否则指纹不可用**）

用 Caddy，自动申请和续期免费证书：

```bash
# 1) 装 Caddy
sudo apt install -y caddy        # debian/ubuntu
brew install caddy                # mac

# 2) 写 Caddyfile
cat > /etc/caddy/Caddyfile <<'EOF'
pb.你的公司.com {
    reverse_proxy 127.0.0.1:8080
}
EOF

# 3) 重载
sudo systemctl reload caddy
```

然后改 `.env`：

```bash
RP_ID=pb.你的公司.com              # 裸域名，不带 https://、不带端口
APP_ORIGIN=https://pb.你的公司.com  # 和地址栏一字不差，末尾不加 /
```

**配错了启动时会明确警告**，不会等到全员打不了卡才发现。
自检结果也在 `curl https://你的域名/api/health` 里能看到。

### 2.5 环境变量速查

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 8080 | 服务端口 |
| `HOST` | 0.0.0.0 | 改成 `127.0.0.1` 就只允许本机访问 |
| `DB_FILE` | `./data/presence.db` | 数据文件位置 |
| `RP_ID` | localhost | WebAuthn 站点标识，**裸域名** |
| `APP_ORIGIN` | `http://localhost:8080` | 浏览器地址栏那个地址，**一字不差** |
| `RP_NAME` | 在岗哨 | 系统弹窗里显示的名字 |
| `ADMIN_PASSWORD` | 空 | 留空则自动生成，写在 `data/.admin-password` |
| `TZ_OFFSET_MINUTES` | 480 | 中国 UTC+8 = 480 |
| `SESSION_TTL_SECONDS` | 45 | 二维码有效期 |
| `REPORT_WEBHOOK_URL` | 空 | 周报推送地址（飞书/企微/Slack 都能接） |
| `REPORT_PUSH_HOUR` | 9 | 每周一几点推送 |
| `TRUST_PROXY` | 关 | 只有确认反代会覆盖 XFF 才设 1 |

### 2.6 第一次启动你会看到

```
┌─────────────────────────────────────────────┐
│  在岗哨 Presence Beacon                      │
├─────────────────────────────────────────────┤
│  员工端   http://localhost:8080/              │
│  管理端   http://localhost:8080/admin         │
│  数据库   .../data/presence.db                │
│  管理员口令 见 .../data/.admin-password       │
└─────────────────────────────────────────────┘
```

管理员口令在 `data/.admin-password`（权限 0600）。**只存哈希，不进日志。**
想自己指定就在 `.env` 里设 `ADMIN_PASSWORD`（至少 12 位）。

## 3. 第一次配置（照着点）

### 3.1 登录管理端

浏览器打开 `https://你的域名/admin` → 输入 `data/.admin-password` 里的口令 → 登录。

### 3.2 添加员工

管理端 → **「员工」** 页 → 「添加员工」：

| 填什么 | 说明 |
|---|---|
| 姓名 | 员工能认出来的名字，重名的话建议带工位区分 |
| 工位 / 岗位 | 用来在周报里区分人，也用于重名时恢复账号 |
| 每周目标（小时） | 默认 24，兼职/弹性岗可以单独改 |

点「添加并生成邀请码」，系统会弹出一对码：

- **邀请码（12 位大写字母数字）** —— 员工第一次登记指纹时用
- **员工码（8 位大写字母数字）** —— 指纹不可用时的兜底通道

> 大小写不用纠结，员工输小写也能通过。

**把这两个码单独发给对应的员工**（微信私聊就行，别群发）。

### 3.3 添加终端

管理端 → **「终端」** 页 → 「添加终端」：

| 填什么 | 说明 |
|---|---|
| 名称 | 比如「办公室前台」 |
| 位置 | 比如「3 楼工位区」 |

点「添加终端」，会生成一条链接，**只显示这一次**：

```
https://你的域名/terminal.html?tid=…&key=…
```

> 链接丢了怎么办？在终端列表点「重置密钥 / 看链接」会生成新链接，
> 旧链接立刻失效。所以**每一台终端用独立的链接**，不要多台设备共用一条。

### 3.4 把旧安卓机变成终端

在旧手机上：

1. 用 Chrome 打开上面那条链接（必须是 `https://`）
2. 浏览器菜单 →「添加到主屏幕」→ 装成 App 图标
3. 装一个 kiosk 浏览器（免 root 的也行），或用 Chrome 的 `chrome://flags` 锁定全屏
4. **关掉系统自动更新**（否则某天早上屏幕会被更新弹窗占满）
5. 插上充电线，设置屏幕常亮
6. 放在工位区而不是门口

屏幕上会看到：不断刷新的二维码 + 倒计时 + 「在场 N 人」。

**长按二维码**可以弹出终端信息面板（终端名、密钥尾号、团队本周合计），方便你核对这台机器是不是对应的那台。

### 3.5 让员工激活自己的手机

告诉每个员工三句话：

> 1. 打开 `https://你的域名/`（在你的手机上）
> 2. 选你的名字 → 输入管理员给你的 **12 位邀请码** → 按一次指纹 / Face ID 完成登记
> 3. 浏览器菜单 →「添加到主屏幕」（之后跟原生 App 一样，点图标直接进）

登记完成后，首页会出现「**签进**」按钮和本周进度条。

### 3.6 跑一次完整演练

**这一步别跳过。** 找一个人真机走一遍：

1. 到办公室 → 点「签进」→ 扫终端二维码 → 按指纹 → 大屏应该亮「张三 已签进」
2. 中间出去吃饭 → 点「签退」→ 扫码 → 按指纹
3. 回来 → 点「签进」→ 扫码 → 按指纹
4. 走的时候 → 点「签退」→ 扫码 → 按指纹

**离开时一定要扫第二次**，否则这段时长不会被计算（系统会按 12 小时自动截断并标「待确认」）。

演练完去管理端 **「周报」** 页，应该能看到这个人的时长条。

## 4. 日常怎么用

### 4.1 员工的一天

| 时刻 | 做什么 |
|---|---|
| 到岗 | 打开 App → 「签进」→ 扫终端码 → 按指纹 |
| 出去吃饭 | 「签退」→ 扫 → 按指纹 |
| 回来 | 「签进」→ 扫 → 按指纹 |
| 走 | 「签退」→ 扫 → 按指纹 |

按钮会根据当前状态自动显示「签进」还是「签退」，**不用自己想该点哪个**。

手滑连按两次会被识别为重复，不会多记一条，也不会把在岗区间提前关掉。

### 4.2 老板的一天

**每天**：不用做任何事。大屏上能看到谁在场。

**每周一**：打开管理端 → 「周报」页 → 看谁达标了。

**每月**：导出 CSV 对账。

### 4.3 管理端五个页面

| 页面 | 干什么 | 什么时候用 |
|---|---|---|
| **周报** | 每个人的本周时长条、目标线、达标与否；团队合计；每日明细表 | 每周一、每月对账 |
| **员工** | 加人、改个人周目标、重置邀请码、离职 | 人来/人走、目标调整 |
| **终端** | 加终端、重置密钥、停用、看终端是否在线 | 换机、终端被搬走 |
| **审批** | 批请假 / 出差 / 补卡申请 | 每天看一眼 |
| **规则** | 改周目标、每日封顶、午休窗口、二维码有效期、时区 | 换季度、调整政策 |

周报页的三个按钮：**← 上一周 / 下一周 → / 导出 CSV**。

导出 CSV 会下载一个真表格（不是错误页面），表头是：
`姓名,工位,在岗小时,目标小时,差值小时,是否达标,出差小时,未签退天数,补卡分钟,补卡次数,员工码打卡次数,状态`

接口地址：`GET /api/admin/export.csv?week=2026-11-23`（需要管理员 token 头 `x-admin-token`）

### 4.4 周报自动推送（可选）

配 `REPORT_WEBHOOK_URL`（飞书 / 企微 / Slack 的 webhook 地址都行），
系统会在每周一 `REPORT_PUSH_HOUR`（默认 9 点）自动推一份文字版周报。

也可以手动推：管理端 → 周报页 → `POST /api/admin/report-push`。

**没配 webhook 的话**：每周一你自己去管理端导出 CSV 发群里。3–5 个人的团队，这一步也就 30 秒。

## 5. 特殊情况怎么处理

### 5.1 请假 / 出差 / 补卡

员工在员工端首页点「**补卡 / 请假 / 出差**」→ 选类型、日期、时长 → 提交。

管理员在管理端「**审批**」页点通过 / 驳回。

| 类型 | 效果 |
|---|---|
| 请假 / 法定假日 / 调休 | 从周目标里**扣除**对应时长（请假 8 小时 → 目标降到 16 小时） |
| 出差 | **既不计入也不抵扣**，周报里单列标记，不会被算成「未达标」 |
| 补卡 | 直接**加上**对应时长（管理员批了才生效） |

补卡和请假都会在周报里显示「补卡 1 次」，**不会偷偷改数**。

### 5.2 员工换了手机 / 清了浏览器缓存

**不用找管理员。** 员工自己在员工端首页点「**以前激活过？点这里恢复**」：

| 方式 | 怎么做 | 强度 |
|---|---|---|
| **用指纹恢复**（推荐） | 填姓名 → 按一次指纹 / Face ID | 强验证，恢复后可以重新登记指纹 |
| **用员工码恢复** | 填姓名（有重名再加工位）+ 8 位员工码 | 弱验证，只能用员工码打卡 |

两条路都**不会产生任何打卡记录**，恢复完照常上班打卡。

接口地址：`POST /api/auth/recover`（姓名 + 工位 + 员工码）；
指纹恢复走 `POST /api/auth/assert-options` → `POST /api/auth/assert-verify`（带 `recover: true`）。

> 为什么要分强弱：员工码是「弱验证」通道。如果拿它就能注册指纹凭证，
> 那拿到员工码的人可以在自己手机上注册一个假指纹，长期占坑别人的打卡通道。
> 所以员工码恢复出来的令牌只够打卡用；想重新登记指纹，得真的按一次指纹。

### 5.3 员工离职

管理端 → 「员工」页 → 对应员工 →「删除」→ 确认。

会发生：停用打卡权限 + 清掉指纹凭据和邀请码 + **保留历史时长**。
这个人在周报里仍会出现，但标为「已离职」，历史时长可追溯（对账、争议时用得上）。

### 5.4 终端旧手机坏了 / 被搬走

- **只是坏了**：管理端「终端」页 → 点「重置密钥 / 看链接」→ 在新手机上打开新链接。
  旧链接立刻失效（别人拿着旧链接也打不了卡）。
  接口地址：`POST /api/admin/terminals/:id/reset-secret`，返回新的 `secret`，管理端自动拼成完整链接。
- **被人搬走了**：同样重置密钥，旧链接作废。再「停用」这台终端，管理端会标记「已停用」。
- **终端离线超过 2 小时**：管理端「终端」页会自动标出「离线超过 2 小时」。
  这期间谁也打不了卡，走补卡流程。

### 5.5 服务挂了 / 断网

- 断网时员工端**仍能打开**（外壳和上次同步的周报都在本地缓存里），
  顶部会挂一条橙色提示「离线模式：显示的是最后一次同步的数据，暂时不能打卡」。
  **不会装作一切正常。**
- 离线时**没法补传打卡**：WebAuthn 的挑战必须由服务器签发，服务端不可达时无法完成指纹验证。
  这是设计上的取舍——宁可让员工事后补卡，也不引入一套更弱的离线认证。

## 6. 时间到底怎么算的

### 6.1 规则参数（管理端「规则」页可改）

参数名和管理端「规则」页上的输入框**一字不差**，可以直接照着填。

| 参数（管理端上的名字） | 默认值 | 说明 |
|---|---|---|
| 周起始日 | 1（周一） | 0=周日 … 6=周六 |
| 默认每周目标（分钟） | 1440 | 24 小时；可按人单独改 |
| 每日封顶（分钟） | 720 | 12 小时，防止连续签到刷时长 |
| 午休窗口开始（分钟） | 720 | 720 = 12:00 |
| 午休窗口长度（分钟） | 60 | 到 13:00 结束 |
| 触发午休扣减的最小覆盖（分钟） | 45 | 在岗区间覆盖午休 ≥ 这么多分钟才扣 |
| 午休扣减时长（分钟） | 60 | 最多扣这段时长的一半 |
| 二维码有效期（秒） | 45 | 每次都不同，截图重放无效 |
| 时区偏移（分钟） | 480 | 中国 UTC+8 |

### 6.2 进/出怎么配对

第 1 次打卡 = 进，第 2 次 = 出，第 3 次 = 进……
每对「进 → 出」产生一个**在岗区间**，所有区间相加 = 当天在岗时长。
空窗（午休、外出）自然不计入。

### 6.3 举几个例子

| 场景 | 结果 | 为什么 |
|---|---|---|
| 9:02 签进 / 18:40 签出 | 当天 **8.6 h** | 一整段区间，午休没有覆盖到 → 不扣 |
| 12:05 签出 / 13:08 签进 | 空窗不计时，当天仍是 8.6 h | 忘了打下班卡才扣午休；正常空窗不重复扣 |
| 一整段 9:00–18:00 没签出 | 扣 1 h → 8 h | 这一段覆盖午休 ≥45 分钟 → 触发扣减 |
| 一天签了 4 次 | 4 个区间相加 | 多次进出都算 |
| 12:00–12:50 只待了 50 分钟 | 这段记 25 分钟 | 扣减最多是这段时长的一半，不会被整段吃掉 |
| 周日 22:00 到 / 周一 02:00 走 | 上周 2 h + 本周 2 h | 跨周按分钟切分，不按「谁先签进算谁那周」 |
| 12 小时封顶 | 最多记 12 h/天 | 防刷 |
| 全员远程的一周 | 规则自动挂起 | 谁都不标「未达标」 |

### 6.4 两个容易误解的点

**「午休扣减」到底扣什么？**
扣的是「你忘了打下班卡，结果一整段区间盖过了午休」这种情况。
你正常打了下班卡（哪怕只离开 5 分钟），空窗本身就不计时，不会再被扣一次。

**「出差」是既不计入也不抵扣。**
出差当天即使你还在公司打了卡，那天的时长也不计入周时长（原始记录仍在明细里），
同时出差**不会**从周目标里扣。所以「出差 3 天 + 在公司 2 天」不会被算成未达标。

## 7. 常见问题排查

| 现象 | 大概率原因 | 怎么修 |
|---|---|---|
| 员工说「这个浏览器不支持指纹验证」 | **不是 HTTPS** | 看地址栏是不是 `https://`。改用域名 + Caddy |
| 员工说「邀请码不正确」 | 输错 / 员工不在名单里 | 管理端「员工」页 →「重置邀请码」生成新的 |
| 员工说「员工码不正确」 | 大小写（系统已兼容）/ 真输错 | 让他试小写；不行就「重置邀请码」 |
| 大屏显示「终端离线」 | 终端密钥错了 / 终端被删了 | 终端列表 →「重置密钥 / 看链接」 |
| 大屏二维码扫不出来 | 摄像头权限被拒 / 浏览器不支持 BarcodeDetector | 员工端有手动输入 8 位码的兜底入口 |
| 员工 iPhone 提示没 Face ID | 手机没开生物识别 | 走员工码通道，事件会标「弱验证」 |
| 周报里某个人时长是 0 | 忘了签退 / 忘了扫码 | 让他提交补卡，你审批 |
| 周报里离职的人还在 | **这是设计**：保留历史时长便于对账 | 标为「已离职」，属正常 |
| 管理端打不开 / 401 | 管理端 token 过期 | 退出重新登录 |
| 服务起不来报 `EADDRINUSE` | 端口被占 | `lsof -ti tcp:8080` 找到并杀掉 |
| 服务起不来报 `database is locked` | 上一个进程没退干净 | 杀掉旧进程；换 `DB_FILE` 重启 |
| 改了规则但没生效 | 没点「保存规则」 | 规则页点「保存规则」 |
| `/api/health` 里 `secure:false` | 没配 HTTPS | 见 2.4 |

**健康检查**：`curl https://你的域名/api/health`

```json
{"ok":true,"secure":true,"origin":"https://pb.你的公司.com","rpID":"pb.你的公司.com",
 "configuredOrigins":["https://pb.你的公司.com"],"employees":5,"terminals":1,"uptimeSec":3600}
```

`secure` 必须是 `true`，否则指纹一定不可用。

## 8. 备份与恢复

SQLite 跑在 WAL 模式，最近的数据可能还躺在 `presence.db-wal` 里。
**直接 `cp data/presence.db` 会丢掉这些数据，而且不报错。**

```bash
npm run backup              # 存到 backups/ 目录
npm run backup /path/to/dir # 存到指定目录
```

脚本会先做一次 WAL checkpoint 再复制出完整快照。
服务也会每分钟自动 checkpoint 一次，让土办法复制也不至于丢太多。

**建议**：加一条 crontab，每天凌晨备份一次。

```bash
0 3 * * * cd /path/to/presence-beacon && /usr/bin/npm run backup >> /var/log/pb-backup.log 2>&1
```

**恢复**：停服务 → 把备份文件拷回 `data/presence.db` → 删掉同目录的 `-wal` / `-shm` → 起服务。

## 9. 安全须知

| 事项 | 做法 |
|---|---|
| 管理员口令 | 只存 scrypt 哈希，不进日志；首次生成在 `data/.admin-password`（0600） |
| 员工码 / 邀请码 | 员工码只存哈希；邀请码 12 位（60 bit 熵）；都有失败锁定 |
| 限流 | 管理员登录 5 次锁 15 分钟；邀请码/员工码 8 次锁 5–10 分钟 |
| 限流键 | 按员工维度，不绑 IP——否则伪造 `X-Forwarded-For` 就能绕过 |
| 终端密钥 | 128 位随机，只存 sha256；明文只在创建/重置时显示一次 |
| 设备令牌 | 首次登记时下发，与员工强绑定；别人的令牌读不到你的数据 |
| 二维码 | 45 秒过期 + 一次性原子占用（并发提交只有一个成功） |
| 生物特征 | 只存在员工手机安全区，服务器拿不到原始指纹/人脸 |

**边界说明**：拿到 `presence.db` 文件 ≈ 拿到全部数据（员工姓名、每周时长、打卡时间）。
这是本地部署的固有边界，请把数据目录放在有权限控制的机器上，别放到网盘同步目录或共享盘。

## 11. 这套东西解决不了什么

说在前面，免得期待错位：

- **指纹挡得住代打卡，挡不住「人在办公室但没干活」**——那本来就不是这套系统要解决的。
- **那台旧手机是单点故障**：它没电/离线时谁都打不了卡。管理端会显示「离线超过 2 小时」，此时走补卡。
- **不要用「连上办公室 WiFi」做判定**，会误伤用手机热点的人。WiFi 只作辅助参考。
- **没有任何打卡系统能防住铁了心要作弊的人。** 3–5 人团队靠**信任 + 周报透明**比靠技术更现实。
